# Экспертная система менеджера здравоохранения (MVP)

ИИ-помощник сотрудника службы поддержки пациентов. По тексту обращения или жалобы на русском или казахском
языке он находит применимые нормы НПА Республики Казахстан и готовит черновик ответа по каждому пункту.
Сотрудник проверяет черновик и сам отправляет ответ заявителю. **Система ничего не отправляет автоматически.**

> В репозитории только **демонстрационные** документы (`data/demo/`). Они вымышлены и не являются НПА РК.
> Реальная база (~1000 документов) загружается парсером после согласования перечня источников.

## Быстрый старт

```bash
cd health-expert
pip install -r requirements.txt
python scripts/serve.py --demo          # http://127.0.0.1:8000
python -m pytest                        # автотесты
```

Вход по демо-токенам: `operator-demo`, `validator-demo`, `admin-demo`. Свои токены задаются переменной
`EXPERT_TOKENS='{"<токен>": {"name": "Ф.И.О.", "role": "operator|validator|admin"}}'`.

### Подключение модели Claude

По умолчанию `settings.toml` → `[llm] provider = "offline"`: это экстрактивный режим без модели. В нём черновик
собирается из выдержек норм, а каждый ответ помечается «требует осторожности». Чтобы подключить внешнюю модель:

```toml
[llm]
provider = "anthropic"
model = "claude-opus-5-5"
```

и задайте `ANTHROPIC_API_KEY`. Во внешнюю модель уходят только обезличенный текст обращения и тексты норм.
Модель подключена через интерфейс `expert/llm/base.py`, поэтому её можно заменить без изменения базы знаний.

### Загрузка реальной базы и обновление

1. Заполните `sources.toml` согласованным перечнем документов (код adilet.zan.kz, орган, блок).
2. `python scripts/update.py` — загрузка и проверка изменений. Для ежедневного запуска добавьте его в cron:
   `0 3 * * * cd /opt/health-expert && python scripts/update.py`.
3. После обновления, в котором что-то изменилось, автоматически запускается регрессионный тест.
   При ухудшении качества администратор получает уведомление.

## Как устроено

```
обращение ─► определение языка ─► обезличивание ─► модель: тип, резюме, вопросы
                                                       │
            ┌──────────────────────────────────────────┘ по каждому вопросу
            ▼
  эталоны / FAQ (быстрый режим) ──совпало──► ответ, подтверждённый человеком
            │ нет
            ▼
  гибридный поиск (BM25 + векторы) по ru и kk, «на дату» ─► модель: черновик
            │                                                  │ (утверждения + id фрагментов + цитаты)
            ▼                                                  ▼
  нет норм ─► «норма не найдена, передайте эксперту»   самопроверка ─► уверенность ─► ok / осторожно / эксперту
```

Главный принцип: модель только выбирает фрагменты и формулирует утверждения. Реквизиты ссылок
(документ, статья, пункт, редакция) система подставляет сама из базы, поэтому выдумать ссылку модель не может.
Цитата попадает в черновик, только если она дословно совпала с текстом нормы.

| Модуль | Назначение |
|---|---|
| `expert/parsing/` | парсер adilet.zan.kz, разбор на главы, статьи и пункты (ru/kk) |
| `expert/ingest.py`, `history.py` | редакции, утрата силы, сравнение, «на дату», переиндексация только изменённого |
| `expert/search.py`, `vectors.py` | гибридный поиск по обоим языкам, заменяемый эмбеддер |
| `expert/anonymize.py` | маскирование ПДн и медицинских данных |
| `expert/llm/` | интерфейс модели, адаптер Claude, офлайн-режим |
| `expert/pipeline.py` | разбор обращения, черновики, три варианта ответа, деградация |
| `expert/verify.py` | самопроверка: ссылки, цитаты, обоснованность, сверка языков, уверенность |
| `expert/quality.py`, `faq.py` | проверка валидатором, эталоны, отчёт, регрессия, FAQ |
| `expert/api.py`, `static/` | API для интеграции и веб-интерфейс |

Соответствие требованиям ТЗ, ограничения MVP и открытые вопросы описаны в [docs/ANALYSIS.md](docs/ANALYSIS.md).
